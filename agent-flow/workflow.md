# Agent 协作工作流

## 核心原则

**做完 > 问完。报告是产出物，不是请求。**

## 决策权限

### 不需要确认（直接做）
- 代码实现、重构、迁移（风险可控）
- 修复 bug、lint error
- 单模块 PoC
- 出报告、更新文档
- 创建/认领 task
- 代码审阅后批准合入

### 需要确认（仅以下）
- 提权操作、危险命令
- 破坏性 API 变更
- 数据迁移（修改存储格式）
- 架构方向重大变更
- 生产环境操作

## 执行节奏

1. 理解需求 → 拆为步骤 → 直接开始第一步
2. 完成一步 → 验证 → commit → 开始下一步
3. 全部完成 → 出报告
4. **不在频道里停等任何人**

## 禁止

- ❌ "要我做 X 吗？" — 直接做
- ❌ "要不要出报告？" — 直接出
- ❌ 完成一批后停等 — 自动推下一批
- ❌ "等 X 回复" — 对方不在就自己做

## 协作

- 各自认领不重叠的模块
- commit message 即状态更新
- 审阅者直接批准，小问题标 nit 不阻塞
- 冲突时在频道快速协调（不等待）

## 报告

- 阶段完成 → 自动出报告
- 格式：完成了什么 + 当前状态 + 剩余项
- 简短，结构化
